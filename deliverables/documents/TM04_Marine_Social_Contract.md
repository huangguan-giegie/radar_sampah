# Team 04 Social Contract - TideTrace MY

**Version 3.0 | 15 August 2026**

> We use short, clear English so every member can explain the demo.

## How we work

- Share a small update when scope, API or safety wording changes.
- Keep one owner and one next action on each LeanKit or GitHub task.
- Use a branch, quick review, merge, integrated test and then deploy.
- Raise a real blocker early. We fix it together.
- Use synthetic/public data and keep source links beside claims.
- Keep detection, missions and progress honest: they are demo outputs, not
  proof of a cleanup or environmental result.

## Communication

We use the Team 04 chat for quick updates and Drive/GitHub for the shared
version. A message says what changed, who is affected and the next action. No
one is expected to answer immediately during class or an exam.

## Review and safety

We check for secrets, broken routes, destructive changes and unsafe claims
first. Small cleanup can follow integration. We do not store identity data,
passwords, API keys or exact coordinates. We do not present a detection or
heatmap as verified evidence.

## Definition of done

A change is done when it has evidence, the integrated demo still runs, docs
match the active flow and the next owner knows the handover. DiveSafe material
stays available as rollback history and is not deleted.
